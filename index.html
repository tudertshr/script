Qu'est-ce qu'un algorithme ?

Un algorithme est une suite finie et ordonnée d'instructions permettant de résoudre un problème de manière automatique et précise.

Caractéristiques d'un bon algorithme :

  • Précis : Chaque instruction est claire et non ambiguë
  • Fini : L'algorithme s'arrête après un nombre fini d'étapes
  • Efficace : Utilise les ressources de manière optimale
  • Général : Résout une classe de problèmes, pas un cas particulier
  • Compréhensible : Facile à lire et à comprendre

Exemple d'algorithme simple

Algorithme 
Algorithme AdditionDeuxNombres
Début
    // Déclaration des variables
    Variables a, b, somme : réels
    
    // Saisie des données
    Écrire("Entrez le premier nombre : ")
    Lire(a)
    Écrire("Entrez le deuxième nombre : ")
    Lire(b)
    
    // Traitement
    somme ← a + b
    
    // Affichage du résultat
    Écrire("La somme est : ", somme)
Fin

Structures de Contrôle en Algorithmique

Structure Conditionnelle :

Syntaxe Si-Sinon 
Si condition Alors
    instructions_si_vrai
Sinon
    instructions_si_faux
Fin Si

Boucle Pour (avec compteur) :

Syntaxe Pour 
Pour i de 1 à 10 Faire
    instructions
Fin Pour

Boucle Tant Que (condition d'entrée) :

Syntaxe Tant Que 
Tant Que condition Faire
    instructions
Fin Tant Que

Boucle Répéter...Jusqu'à (condition de sortie) :

Syntaxe Répéter 
Répéter
    instructions
Jusqu'à condition

Portée des variables :

  • Variable globale : Déclarée en début d'algorithme, accessible partout
  • Variable locale : Déclarée dans une fonction/procédure, accessible uniquement dans cette fonction
  • Variable de boucle : Déclarée dans une boucle (comme i dans "Pour i de 1 à 10"), accessible uniquement dans la boucle

Notations Algorithmiques

  • = ou == : Égal à
  • ≠ ou != : Différent de
  • < : Strictement inférieur à
  • > : Strictement supérieur à

  • ≥ ou >= : Supérieur ou égal à

  • et ou AND : ET logique
  • ou ou OR : OU logique

Opérateurs arithmétiques :

Langages Compilés vs Langages Interprétés

Comparaison : Langages Compilés vs Interprétés

Caractéristique Langage Compilé Langage Interprété
Définition Le code source est traduit en langage machine avant l'exécution Le code source est exécuté ligne par ligne par un interpréteur
Processus Compilation → Exécution Interprétation directe
Vitesse d'exécution Plus rapide (code machine optimisé) Plus lente (interprétation à la volée)
Portabilité Moins portable (dépend de l'architecture) Plus portable (interpréteur seul à adapter)
Débogage Plus difficile (erreurs à la compilation) Plus facile (erreurs à l'exécution)
Exemples C, C++, Pascal, Fortran Python, JavaScript, PHP, Ruby

Langages Semi-Compilés (Bytecode)

Certains langages comme Java et C# utilisent une approche hybride :

  • Compilation : Code source → Bytecode (code intermédiaire)
  • Exécution : Bytecode → Machine virtuelle (JVM pour Java, CLR pour C#)
  • Avantages : Portabilité + performances raisonnables

Exécution d'un Programme

Cycle de vie d'un programme :

  1. Écriture du code source : Programmeur écrit le code dans un langage de haut niveau
  2. Compilation/Interprétation : Transformation du code source en langage exécutable
  3. Chargement en mémoire : Le système d'exploitation charge le programme en mémoire RAM
  4. Exécution par le CPU : Le processeur exécute les instructions une par une
  5. Gestion des entrées/sorties : Interaction avec l'utilisateur et les périphériques
  6. Fin d'exécution : Libération des ressources mémoire

Rôle du système d'exploitation :

  • Gestion de la mémoire : Allocation et libération d'espace mémoire
  • Ordonnancement des processus : Déterminer quel programme s'exécute à quel moment
  • Gestion des entrées/sorties : Communication avec les périphériques
  • Sécurité : Protection des ressources et isolation des processus

Niveaux de Langage de Programmation

Pyramide des niveaux de langage :

Niveau Description Exemples Caractéristiques
Langage machine Instructions directement exécutables par le CPU (binaire) Code binaire (0 et 1) Très rapide, difficile pour l'humain
Langage d'assemblage Représentation symbolique du langage machine Assembleur (MOV, ADD, JMP) Plus lisible, dépendant du processeur
Langage de bas niveau Proche du matériel, contrôle fin des ressources C, C++ Performant, gestion manuelle de la mémoire
Langage de haut niveau Abstraction du matériel, proche du langage humain Python, Java, JavaScript Facile à apprendre, moins performant
Langage très haut niveau Orientation métier, abstraction maximale SQL, HTML, MATLAB Spécialisé, productivité élevée

Évolution des langages :

Les langages ont évolué des langages impératifs (COBOL, Fortran) vers les langages orientés objet (Java, C++) et maintenant vers les langages multi-paradigmes (Python, JavaScript) qui combinent plusieurs approches.

Processus de Compilation

Les 4 phases de la compilation :

  1. Analyse lexicale : Découpe le code source en tokens (mots-clés, identifiants, opérateurs)
  2. Analyse syntaxique : Vérifie la structure grammaticale du programme (arbre syntaxique)
  3. Analyse sémantique : Vérifie la cohérence logique (types, déclarations, portée)
  4. Génération de code : Produit le code machine ou intermédiaire optimisé

Outils de compilation :

  • Compilateur : Traduit tout le programme en une fois (gcc pour C, javac pour Java)
  • Interpréteur : Exécute le programme ligne par ligne (python, ruby)
  • Assembleur : Traduit le langage assembleur en langage machine
  • Éditeur de liens : Combine plusieurs fichiers objets en un exécutable unique

Rappel sur les tableaux

Un tableau (ou vecteur) est une structure de données qui permet de stocker plusieurs valeurs de même type sous un seul nom. Chaque élément est accessible via un indice.

Déclaration d'un tableau :

Syntaxe 
// Déclaration d'un tableau de 100 entiers
Variables T : tableau[100] d'entiers

// Déclaration avec initialisation
Variables notes : tableau[5] de réels ← {12.5, 15.0, 10.0, 18.5, 14.0}

Attention : Les indices commencent généralement à 0 ou à 1 selon la convention utilisée. Dans nos exemples, nous utiliserons des indices commençant à 0.

Ex 7
Tri par sélection

Trier un tableau par ordre croissant avec l'algorithme de tri par sélection.

Algorithme 
Algorithme TriSelection
Début
    Variables T : tableau[100] d'entiers
    Variables n, i, j, min, temp : entiers
    
    Écrire("Nombre d'éléments : ")
    Lire(n)
    
    Si (n <= 0) ou (n > 100) Alors
        Écrire("Erreur : n doit être entre 1 et 100")
    Sinon
        // Lecture du tableau
        Pour i de 0 à n-1 Faire
            Écrire("T[", i, "] = ")
            Lire(T[i])
        Fin Pour
        
        // Tri par sélection
        Pour i de 0 à n-2 Faire
            min ← i
            Pour j de i+1 à n-1 Faire
                Si T[j] < T[min] Alors
                    min ← j
                Fin Si
            Fin Pour
            
            Si min ≠ i Alors
                temp ← T[i]
                T[i] ← T[min]
                T[min] ← temp
            Fin Si
        Fin Pour
        
        // Affichage du tableau trié

Définition d'une fonction en algorithmique

Une fonction est un sous-algorithme qui retourne une valeur. Une procédure est un sous-algorithme qui ne retourne rien (équivalent à une fonction void en C).

Structure d'une fonction :

Syntaxe Fonction 
Fonction nomFonction(param1: type1, param2: type2): typeRetour
Début
    // Instructions
    Retourner valeur
Fin

Structure d'une procédure :

Syntaxe Procédure 
Procédure nomProcedure(param1: type1, param2: type2)
Début
    // Instructions
Fin

Différence entre fonction et procédure :

  • Fonction : Retourne une valeur, peut être utilisée dans une expression
  • Procédure : Ne retourne rien, appelée pour son effet (affichage, modification de paramètres)
  • Paramètres : Peuvent être passés par valeur (copie) ou par référence (modifiable)

Début

    Retourner resultat

Fin

Tri à bulles (Bubble Sort) :

Algorithme 
Algorithme TriBulles
Début

    Variables n, i, j, temp : entiers
    Variable echange : booléen

Principes du tri à bulles :

  • Comparer les éléments adjacents et les échanger s'ils ne sont pas dans l'ordre
  • À chaque passage, le plus grand élément "remonte" vers sa position finale
  • Optimisation : arrêter si aucun échange n'a été fait (tableau déjà trié)
  • Complexité : O(n²) dans le pire cas, O(n) dans le meilleur cas (tableau déjà trié)

    Variables T : tableau[100] d'entiers
    Variables n, i, x, debut, fin, milieu : entiers
    Variable trouve : booléen
    
    Écrire("Nombre d'éléments (tableau doit être trié) : ")
    Lire(n)
    
    Si (n <= 0) ou (n > 100) Alors
        Écrire("Erreur : n doit être entre 1 et 100")
    Sinon
        // Lecture du tableau trié
        Écrire("Saisie des éléments en ordre croissant :")
        Pour i de 0 à n-1 Faire
            Écrire("T[", i, "] = ")
            Lire(T[i])
            
            // Vérification que le tableau est bien trié
            Si (i > 0) et (T[i] < T[i-1]) Alors
                Écrire("Erreur : le tableau n'est pas trié !")
                Sortir
            Fin Si
        Fin Pour
        
        Écrire("Élément à rechercher : ")
        Lire(x)
        
        // Recherche dichotomique
        debut ← 0
        fin ← n-1
        trouve ← FAUX
        
        Tant Que (debut <= fin) et (trouve = FAUX) Faire
            milieu ← (debut + fin) DIV 2
            
            Si T[milieu] = x Alors
                trouve ← VRAI
            Sinon Si x < T[milieu] Alors
                fin ← milieu - 1
            Sinon
                debut ← milieu + 1
            Fin Si
        Fin Tant Que
        
        // Affichage du résultat
        Si trouve = VRAI Alors
            Écrire(x, " trouvé dans le tableau")
        Sinon
            Écrire(x, " non trouvé")
        Fin Si
    Fin Si
Fin

Principes de la recherche dichotomique :

  • Nécessite un tableau trié
  • Divise l'intervalle de recherche par deux à chaque étape
  • Compare l'élément du milieu avec l'élément recherché
  • Complexité : O(log n) - très efficace pour les grands tableaux
  • Complexité de la recherche séquentielle : O(n)

Algorithme d'Euclide (PGCD) :

Algorithme 
Algorithme PGCDEuclide
Début
    Variables a, b, temp : entiers
    
    Écrire("Entrez le premier nombre : ")
    Lire(a)
    Écrire("Entrez le deuxième nombre : ")
    Lire(b)
    
    // Gestion des nombres négatifs
    Si a < 0 Alors
        a ← -a
    Fin Si
    
    Si b < 0 Alors
        b ← -b
    Fin Si
    
    // Algorithme d'Euclide
    Tant Que b ≠ 0 Faire
        temp ← b
        b ← a MOD b
        a ← temp
    Fin Tant Que
    
    Écrire("PGCD = ", a)
Fin

Autres algorithmes importants :

  • Tri rapide (QuickSort) : Algorithme de tri récursive basé sur le principe "diviser pour régner"
  • Tri par fusion (MergeSort) : Autre algorithme "diviser pour régner" avec complexité O(n log n)
  • Recherche du plus court chemin : Algorithmes de Dijkstra, Floyd-Warshall
  • Algorithmes de parcours de graphes : Parcours en largeur (BFS), parcours en profondeur (DFS)
  • Algorithmes de compression : Algorithme de Huffman

Fiche de Révision et Conseils pour l'Examen

Checklist pour réussir en algorithmique

  1. Comprendre le problème avant de coder (lire attentivement l'énoncé)
  2. Identifier les entrées/sorties du programme
  3. Choisir les structures de données appropriées (tableau, matrice, etc.)
  4. Décomposer le problème en sous-problèmes plus simples
  5. Écrire l'algorithme en pseudo-code d'abord, puis traduire si nécessaire
  6. Tester avec des cas simples avant de généraliser
  7. Vérifier les cas limites et les erreurs potentielles (divisions par zéro, indices hors limites)
  8. Optimiser si nécessaire après avoir une solution fonctionnelle
  9. Commentez votre code pour expliquer votre raisonnement
  10. Relisez-vous pour corriger les erreurs évidentes

Conseils pour les examens

  • Gérer votre temps : Allouez du temps pour la lecture, la conception, l'écriture et la relecture
  • Commencez par les exercices faciles pour gagner des points rapidement
  • Lisez toutes les questions avant de commencer pour avoir une vue d'ensemble
  • Commentez votre code pour montrer votre raisonnement même si le code n'est pas parfait
  • Testez mentalement votre algorithme avec des valeurs simples (0, 1, valeurs négatives)
  • Vérifiez les cas limites (tableau vide, valeurs extrêmes, etc.)
  • Ne restez pas bloqué sur une question, passez à la suivante et revenez plus tard
  • Relisez-vous pour corriger les erreurs évidentes (fautes de syntaxe, variables non déclarées)

Erreurs fréquentes à éviter

  • Oublier de déclarer les variables avant de les utiliser
  • Débordement d'indices dans les tableaux (accès à T[n] alors qu'il n'y a que n éléments)
  • Division par zéro sans vérification préalable
  • Boucles infinies (oubli d'incrémenter la variable de boucle)
  • Confusion entre = (affectation) et == (comparaison)
  • Mauvaise gestion des conditions (utiliser ET à la place de OU ou inversement)
  • Oublier les guillemets pour les chaînes de caractères
  • Ne pas initialiser les variables avant de les utiliser dans des calculs
